新增检查覆盖：

- 比较页创建后保持PENDING，不能自动批准。
- 明确批准需要审核者、意见及完整逐层审核确认；REJECTED/NEEDS_MANUAL_EDIT阻止后续。
- 用户会话中明确批准时，另存批准原文与EXPLICIT_USER_APPROVAL依据；不虚构reviewed_all_slices=true，输入和掩膜哈希检查仍全部执行。
- 修改T1、mask或比较清单后旧批准无效。
- ITK-SNAP独立编辑副本保留原候选；手修导入拒绝错网格，修后重新审核。
- 仅导出审核T1/mask，不带旧组织分割或标准化变换。
- 新容器计划必须绑定审核和原BIDS T1；容器退出后逐体素核对实际原生mask，防止导入无效却悄悄再次提取。
- 复用输入未被后端重复写入原生输出目录时，可以核对实际Nipype掩膜应用/强度截断/配准节点记录、实际输入mask和应用后的体素。不能复制批准mask到输出目录冒充后端采用证据。本地九分支解剖对照已由专用控制器采集此证据；通用启动器不自动采集该运行时证据，不能把这次对照当成通用启动器全部验收。
- 在启动前要求辅助neo_bids_filter.json的精确.bidsignore条目，防止把辅助配置当作不合规影像文件；MRI文件不能据此被忽略。
- 拒绝无审核、用旧mask结果冒充新mask配准、标准化影像与模板网格不一致。
- 合成错位影像生成两个不同GIF帧及可暂停/单显的HTML，registration_fits=0。
- 小尺寸切片可以放大到屏幕，非等距体素保留物理纵横比；只改变显示尺寸，不重采样三维数据。
- 候选命令计划不启动计算，CPU4，拒绝超过1800秒预算。

真实三例候选生成与代码合成测试是两类证据。候选能计算、网格有效、文件同步一致不等于人工通过。本地九分支解剖对照已完成，实际采用mask、输出哈希和数值QC已核验，用户明确批准本轮mask及MNI结果；这不批准未来新输入，也不构成临床验证。HD-BET依赖在独立Linux环境，核心Python锁未合并或升级。

新HTML的真实浏览器交互验收独立于Python数值测试；如只运行模拟DOM，应如实注明，不能称为专家读片。真实影像与本地审核记录不进入公共CI或Git。

`tests/test_anatomy_viewer.cjs`可对生成的本地HTML进行Node DOM/canvas模拟检查：gzip解码、候选切换、完整/保留/排除/差异、透明度实时输入、三面点击联动、滚轮和切片滑条，以及闪烁暂停、单显、间隔边界。用法：`node tests/test_anatomy_viewer.cjs /path/to/review.html /path/to/blink.html`。它不安装或启动浏览器，不能替代真实浏览器兼容性、布局或人工解剖审核。当前自动浏览器工具拒绝file://本地页访问，因此本轮采用模拟交互与独立静态图检查；实际本地Chrome/Edge打开仍需另验。
